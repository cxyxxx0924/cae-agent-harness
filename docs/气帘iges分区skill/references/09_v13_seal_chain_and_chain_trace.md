## 3. 方法论沉淀：chain_trace.py「沿顺滑方向追链」

**用户明示要作为技能**：找边界链不要逐根肉眼猜，要"沿着它顺滑的方向去寻找"。
三条规则：

1. **编号顺序**：边界线在 IGES 里通常按绘制顺序连续编号（167→168→169→…）。
   种子线两端都接其他线时，**优先沿「邻居线号 = seed+1」的方向**进入——
   这一条在 L167 分叉处（左接 L168、右接 L253）一锤定音。
2. **顺滑方向**：真边界相邻段转向角小、大致同向。容差内多候选时按
   `score = 0.6×方向连续 + 0.2×偏好方向 + 0.2×编号接近` 打分。
3. **精确衔接优先**：先查端点精确距离（0.00mm 级），容差模糊匹配（2mm）
   只用于跨图纸微缝——**不要用大容差做全局 flood**（楔顶多线共点会洪水连通）。

用法：

```bash
python chain_trace.py --geom out/geom_features.txt --classify out/classify_v13.json \
    --seed 167 --pref "0,1" --number-order --stoppts "834.9,497.4"
```

输出 FORWARD/BACKWARD 两条链。实测 FORWARD = L167→L168→L169→L170→L172 后
踩进 L198→L154→…→L161 旁支（端口区域是近重合线团，见坑 P51）——**追链器
输出必须用精确端点衔接复核**，本例链的权威判据是 0.00/0.06mm 衔接表（§1）。

## 4. 坑位

- **P49（t08 旧报告误判）**：`t08_verify_partitioned.tcl` 第 4 行 `set P $::env(WORKDIR)`
  **必须设 WORKDIR**；漏设则 hmbatch 立即出错退出（`HM exiting with code 1`）且
  **报告文件不更新**，看到的 `VERIFY_FAIL=0` 是上一版遗留 —— v13 第一次校验就栽在这
  （读到 v12 旧报告 36/84，差点当 PASS 交付）。对策：跑 t08 前 `rm -f out/verify_partitioned.txt`，
  跑后必须核对报告里的 COUNT 与本次 p06 输出一致。
- **P50（零长度线）**：端口白线里有退化线（L171 len=0.0，两端点同位），追链和
  分类都应跳过，混进 comp 会在建面时产生零长度边。
- **P51（端口近重合线团）**：充气口区域存在大量近乎重合的线（L198 与 L172 末端
  0.5mm 搭接、L154 与 L169 平行 1mm），纯几何容差追链会拐进旁支。锁链的权威判据
  是**精确端点衔接 + 编号连续**，容差追链只作参考。
- **P52（QA 容差 0.05mm 的边界效应）**：L170-L172 实际 0.06mm、L188-L196 0.23mm，
  严格 0.05mm QA 会把闭环拆成 3 个组分显示"开环"。这不是分类错误——图纸固有微缝
  按约定留给建面/共节点阶段桥接（P47），读 QA 报告时先查断点距离量级再下结论。
