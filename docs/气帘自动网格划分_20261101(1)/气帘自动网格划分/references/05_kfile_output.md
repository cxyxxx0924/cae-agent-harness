# 05 · K 文件写法 + 交付门禁

> 配套 `scripts/qa_kfile_strict.py`（P20）。本文件讲"怎么写才不会被 HM 读死机"，
> 是从 P1 / P18 / P20 抽象出的通用写法规则，step1 与 tabs 两套写入脚本共用。

---

## 1. 字段顺序铁律（P1 的抽象）

LS-DYNA 关键字**位置敏感**，不是按字段名解析。错一列，整表错位。

| 卡 | 必写列（位置顺序） |
|---|---|
| `*NODE` | `nid, x, y, z`（逗号自由格式，见 §3） |
| `*ELEMENT_SHELL` | `eid, pid, n1, n2, n3[, n4]`（**eid 是第一列，漏写即 P1 死机**） |
| `*PART` | `pid, secid, mid`（数据行；title 行是字符串） |

**四节点单元写 6 列，三节点写 5 列**。把四节点写成 `n4==n3` 的退化四边形 =
"重复节点"，违反公司规范"禁止重复单元与重复节点"（P18），部分读取器报警 → 一律写 5 列三角。

## 2. 两种合法格式（二选一，不得混用也不得自创宽度）

### 2.1 逗号自由格式（首选，零歧义 + 全精度）
```
100001, 1236.052648, 0.000000, 984.317205
80465, 5, 42423, 42417, 40843, 40876
```
- 坐标用全精度（`f"{x:.6f}"` 或更高），**4 位整数 + 6 位小数（如 1236.052648）放不进 10 字符定宽** → 必须用自由格式。
- QA 读取器按 `split(",")` 解析，绝不按定宽切分。

### 2.2 严格 10 字符定宽（仅当坐标位数很小、确定放得下时用）
```
         1         2         3  ...（每字段 10 字符，左对齐或右对齐一致即可）
```
- **绝不能用"nid(10)+x(16)+y(16)+z(16)"这种自创混合宽度**（P1 翻车现场：y 读到 x 小数尾、z 读到 0 → 节点全塌到 z=0 平面）。
- 如果拿不准，用 2.1 自由格式，别赌定宽。

## 3. 写入器与 QA 必须"对抗式独立"（P20 核心）

P1 翻车的直接原因：**诊断脚本和写入器共享同一套字段假设**，回读永远"正确"。

`qa_kfile_strict.py` 的原则：
- **独立解析**，不 import 任何写入脚本、不复用其字段常量（字段顺序硬编码在 QA 文件头）。
- 检查项比真实读取器更严：
  - 纯 ASCII（非 ASCII 字节 → 直接拒，HM 中文路径/中文注释会触发）
  - `eid` 唯一且 > 0
  - 单元 `pid` 必须 ⊆ `*PART` 的 pid 集合（幽灵 part 会卡死 HM）
  - 单元引用的 `nid` 必须存在且 > 0
  - **无重复单元**（同节点集，无序比对 `tuple(sorted(ns))`）
  - 单元内无重复节点
  - `*SECTION` / `*MAT` 引用完整
- 退出码 **0 = 可交付，1 = 禁止交付**，可挂流水线门禁。

> `*PART` 数据行可能无逗号（定宽/空格分隔），QA 必须先按"能否转数值"判定，
> 不能先 `split(",")`（会把数据行误当 title → pid 全漏）。
