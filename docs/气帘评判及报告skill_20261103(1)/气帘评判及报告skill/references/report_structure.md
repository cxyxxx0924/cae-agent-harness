# 报告结构与写法

> 目标：让客户拿着这份报告能直接回答"哪条判据、什么证据、判了什么、还缺什么"。
> 版式沿用它自己的模板（蓝白、深蓝标题条、页脚页码），内容按下面四段组织。

## 一、四段式骨架

| 段 | 页数 | 作用 | 缺了会怎样 |
| --- | --- | --- | --- |
| 00 封面 + 目录 | 1–2 | 谁、什么件、什么依据、什么日期 | 客户不知道适用范围 |
| 01 依据与差异 | 2–3 | 参考报告 vs 法规的定位差异 | 客户以为"厚度=合规" |
| 02 判据逐条解读 | 4–6 | 每条判据的含义、阈值、测量条件 | 后面所有结论失去锚点 |
| 03 CAE 判定链路 | 2–3 | 数据从哪来、怎么量、能判到哪 | 结论无法复现 |
| 04 结果与结论 | 3–5 | 实测数据、图、三档结论 | 报告没有交付物 |

一份 15–19 页的报告，按上面的配比最稳。客户模板本身是 13 页（研究型），法规评价需要多出"判据"和"链路"两段。

## 二、每页必备要素

### 判据页（02 段）
- 条文编号（如 G.14.3.1.3 a）——没有编号，客户无法回溯；
- **阈值 + 单位 + 测量条件**（静态展开 / 0.1–0.4 bar / 评估区域内）；
- 一句"为什么这么规定"（物理机理），不超过两行；
- 常见误读提示（如果有）。

### 链路页（03 段）
- 数据源（文件名 + 格式 + 状态数 + 时间范围）；
- 算法一句话（例："双层壳按初始态配对，厚度 = 变形后 Y 向距离"）；
- 能判/不能判的边界（表格形式最省字数）。

### 结果页（04 段）
- 一张图 + 一张表，图给直观、表给数字，两者必须对得上；
- 表里每个数字带**坐标基准**和**时刻**；
- 结论用三档（PASS / FAIL / INDETERMINATE），并写清"缺什么才能升级结论"。

## 四、沿用客户模板的做法

1. **先扒主题**：`unzip pptx` 后读 `ppt/theme/theme1.xml` 的 `clrScheme` + `fontScheme`。本例主色 `#005496`，强调 `#009FE3`，正文 `#474C4F`，标题字号 46/40/44。
2. **标题条与页脚**：内容页统一"左上标题 + 右上页码 + 底部细线"，占位高度保持一致（本例标题条 72 px）。
3. **分隔页**：大号浅色数字（`fontSize: 200`，色 `#E3EEF8`）+ 章节名，是这类模板的标志性元素，保留。
4. **图片直接取原 pptx 里的图**：`ppt/media/imageNN.png`，比截图清晰，也不受渲染环境限制。
5. **表格风格**：表头深蓝底白字、行分隔细线、数值右对齐。字号 16–18，别小于 14。

## 五、自检（每次交付前跑）

```bash
# 1) 逐页结构校验
slidep lint deck.pptx --dsl-file slides/NN.slide --page-index NN

# 2) 页面边界：所有元素右下角必须 <= 720
#    解析 inspect 出来的 slides.md，抓 "右下 x,y" 取 max(y)
# 3) 图片比例：解压 pptx，逐个 <p:pic> 读 a:off/a:ext，核对 h/w 与原图像素比
```

判据：`max(bottom) ≤ 720`；图片 `h/w` 与源图比例误差 ≤ 2%。

## 六、已交付案例的段落划分（19 页，R676 气帘）

| 页 | 内容 |
| --- | --- |
| 1–2 | 封面、目录 |
| 3–5 | 01 两份文档定位比对（分隔页 + 对比表） |
| 6–11 | 02 判据逐条解读（分隔页配 HPD→Flat IC 原图、三项罚分、评估区域尺寸链、缝线/斑、动态保护） |
| 12–14 | 03 CAE 判定链路（分隔页、链路表、阈值） |
| 15–16 | 04 结果：落点越界分析、缝线/覆盖统计 |
| 17–18 | 04 结果：厚度测量方法 + 云图、五点厚度表 + 时程 |
| 19 | 结论与下一步（缺什么、怎么补） |

这套划分可直接复用，只换数据与图。
